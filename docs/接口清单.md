# 接口清单

> 项目名称：城市出租车运营管理与决策支持系统
> 后端框架：FastAPI 0.110（OpenAPI 3.1）
> 接口数量：**12 个业务模块，78 个路径，96 个操作**
> 事实来源：本文档的路径、方法、参数、响应模型均由运行中的应用直接导出 ——
> `from app.main import app; app.openapi()`，未作任何手工补全。

### 1.2 统一鉴权方式

除下表列出的 **3 个公开接口**外，其余所有接口都要求携带 JWT 令牌：

```http
Authorization: Bearer <access_token>
```

| 公开接口（无需令牌） |
| --- |
| `POST /api/auth/login` |
| `GET /` |
| `GET /api/health` |

令牌获取方式：

```http
POST /api/auth/login
Content-Type: application/json

{"username": "admin", "password": "admin123"}
```

响应：

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9....",
  "token_type": "bearer",
  "expires_in": 86400
}
```

鉴权失败的统一响应（状态码 **401**）：

```json
{"detail": "登录状态无效或已过期，请重新登录"}
```

响应头附带 `WWW-Authenticate: Bearer`。触发条件包括：未携带 `Authorization` 头、令牌格式非法、签名校验失败、令牌已过期、载荷缺少 `sub`、`sub` 对应的用户不存在。

**权限分级约定**（本文档接口表的「权限」列）：

| 权限标记 | 含义 | 后端实现 |
| --- | --- | --- |
| 公开 | 无需令牌 | 无鉴权依赖 |
| 登录 | 需要有效的登录令牌，任意角色均可 | 依赖 `get_current_user` |
| admin | 需要系统管理员角色 | 依赖 `require_admin`（内部已包含 `get_current_user`） |

非管理员访问 admin 接口时的响应（状态码 **403**）：

```json
{"detail": "无权限执行该操作（需要管理员）"}
```

### 1.3 统一错误响应格式

**（1）业务错误与鉴权错误**——由 `HTTPException` 产生，响应体为单字段对象，`detail` 为中文描述：

```json
{"detail": "用户名或密码错误"}
```

**（2）请求参数校验错误**——由 FastAPI + Pydantic 产生，状态码 **422**，`detail` 为数组：

```json
{
  "detail": [
    {
      "type": "greater_than_equal",
      "loc": ["query", "page"],
      "msg": "Input should be greater than or equal to 1",
      "input": "0",
      "ctx": {"ge": 1}
    }
  ]
}
```

**（3）未捕获异常**——由全局异常处理器统一转换，状态码 **500**：

```json
{"detail": "服务器内部错误：<异常信息>"}
```

> 设计意图：不把堆栈直接暴露给前端，但仍返回异常摘要以便定位问题。

前端 axios 拦截器对 `detail` 做了兼容处理：字符串直接提示；数组则拼成「字段: 消息」的形式提示。

### 1.4 分页请求与响应约定

**请求参数**（由 `core/deps.py :: PageParams` 统一提供，所有分页接口共用同一套参数名与约束）：

| 参数 | 类型 | 必填 | 默认值 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `page` | integer | 否 | `1` | ≥ 1 | 页码，从 1 开始 |
| `page_size` | integer | 否 | `20` | 1 ~ 500 | 每页条数 |

**响应结构**（由 `schemas.Page[T]` 统一约束）：

```json
{
  "total": 59944,
  "page": 1,
  "page_size": 20,
  "items": []
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `total` | integer | 满足筛选条件的总记录数（已排除排序开销） |
| `page` | integer | 当前页码（原样返回） |
| `page_size` | integer | 每页条数（原样返回） |
| `items` | array | 当前页数据，元素类型由各接口的响应模型决定 |

**使用分页的接口**（共 13 个）：区域列表、车辆列表、驾驶员列表、绑定记录列表、营运订单列表、叫车请求列表、调度方案列表、调度单列表、操作日志、用户列表。

> 说明：分析类、驾驶舱类接口返回的是聚合结果（如 24 条时段数据、7 条星期数据），数据量固定且很小，因此**不使用分页**。

**非分页的通用响应模型**：

| 模型 | 字段 | 说明 |
| --- | --- | --- |
| `Message` | `message: string`（必填） | 操作结果提示，如「删除成功」「状态已更新」「已解绑」 |
| `ImportResult` | `success: boolean = true`、`total_rows: integer = 0`、`imported: integer = 0`、`duplicated: integer = 0`、`error_rows: List[integer] = []`、`error_messages: List[string] = []` | Excel 导入结果 |
| `Token` | `access_token: string`（必填）、`token_type: string = "bearer"`、`expires_in: integer = 0` | 登录令牌 |

### 1.5 日期格式约定

| 场景 | 格式 | 示例 | 说明 |
| --- | --- | --- | --- |
| 日期（请求与响应） | `YYYY-MM-DD` | `2026-10-01` | 对应 Pydantic `date` 类型 |
| 日期时间（请求与响应） | ISO 8601 | `2026-10-01T08:15:00` | 对应 Pydantic `datetime` 类型，序列化时不带时区后缀 |
| 日期区间参数 | 两个独立参数 `start_date` / `end_date` | `?start_date=2026-09-01&end_date=2026-09-30` | **闭区间**语义（含首尾两天）；后端统一转换为 `[start 00:00:00, end+1天 00:00:00)` 的半开区间查询 |
| 区间缺省行为 | 只传 `end_date` → 从 `end - (N-1) 天` 开始；只传 `start_date` → 到 `start + (N-1) 天` 结束；都不传 → 取最近 N 天 | — | N 为各接口的 `default_days`，见下表 |
| 时间序列分组 | `group_by` 参数 | `hour` / `day` / `week` / `month` | SQL 侧按方言生成日期截断表达式（MySQL `DATE_FORMAT` / SQLite `strftime`） |
| 时间精度 | 存储到秒 | `2026-10-01 08:15:32` | 仿真数据在分钟与秒位上随机 |
| 汇率/时区 | 无 | — | 单机单时区部署，不处理时区转换 |

**各接口的默认统计天数**

| 接口 | 默认天数 |
| --- | --- |
| `GET /api/analysis/overview`、`income-trend`、`hourly-profile`、`region-ranking`、`region-compare`、`load-rate`、`driver-ranking`、`vehicle-efficiency`、`pay-type`、`weather-impact`、`dashboard` | 30 |
| `GET /api/analysis/weekday-profile` | 56（8 周，保证每周都有完整样本） |
| `GET /api/analysis/heatmap` | 28（4 周） |
| `GET /api/operation/`（未传日期时） | 30 |
| `GET /api/demand/`（未传日期时） | 7 |
| `GET /api/demand/summary`（未传日期时） | 7 |
| `GET /api/demand/region-hour-matrix`（未传日期时） | 14 |
| `GET /api/demand/weekday-hour`（未传日期时） | 28 |

## 3 典型接口详解

### 3.1 用户登录

**请求**

```http
POST /api/auth/login HTTP/1.1
Host: localhost:8000
Content-Type: application/json

{
  "username": "admin",
  "password": "admin123"
}
```

**成功响应** `200 OK`

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJhZG1pbiIsInJvbGUiOiJhZG1pbiIsImV4cCI6MTc5MzM0NzIwMH0.tK7x9Qm2vYq8Lp3sR1nB4cW6dZ0aF5gH8jK2mN4pQ6s",
  "token_type": "bearer",
  "expires_in": 86400
}
```

**典型失败响应**

| 场景 | 状态码 | 响应体 |
| --- | --- | --- |
| 用户名不存在或口令错误 | 400 | `{"detail": "用户名或密码错误"}` |
| 账号已被禁用 | 403 | `{"detail": "账号已被禁用，请联系管理员"}` |
| 用户名长度不足 2 位 | 422 | `{"detail": [{"type": "string_too_short", "loc": ["body", "username"], "msg": "String should have at least 2 characters", "input": "a", "ctx": {"min_length": 2}}]}` |

**说明**

- `expires_in` 为**秒**，等于 `ACCESS_TOKEN_EXPIRE_MINUTES × 60`，默认 1440 分钟即 86400 秒。
- 响应模型为 `Token`，字段为 `access_token`、`token_type`、`expires_in`；**不含**用户信息，需另调 `GET /api/auth/me` 获取。
- 登录成功会更新 `sys_user.last_login`。
- 该接口是全局**唯一**不需要令牌的业务接口。

## 4 错误码说明

系统使用的 HTTP 状态码共 5 类，含义与常见触发场景如下。

### 4.1 400 Bad Request —— 业务规则不通过

表示「请求格式正确、身份合法，但不满足业务规则」。响应体的 `detail` 为中文说明，多数情况下会告诉用户下一步该怎么做。

| 常见触发场景 | detail 文本 |
| --- | --- |
| 登录口令错误或用户名不存在 | 用户名或密码错误 |
| 修改密码时原密码错误 | 原密码不正确 |
| 新增/修改车辆时车牌号重复 | 车牌号已存在 |
| 新增/修改驾驶员时身份证号重复 | 身份证号已存在 |
| 新增/修改区域时区域编码重复 | 区域编码已存在 |
| 新增营运订单时订单号重复 | 订单号已存在 |
| 营运订单的下车时间早于上车时间 | 下车时间不能早于上车时间 |
| 营运订单引用的车辆/驾驶员不存在 | 车辆不存在 / 驾驶员不存在 |
| 叫车请求引用的区域不存在 | 区域不存在 |
| Excel 缺少必要列 | 缺少必要列：xxx、yyy。请先下载导入模板。 |
| Excel 文件无法解析 | 文件解析失败：&lt;原因&gt; |
| 删除已产生营运记录的车辆 | 该车辆已产生 N 条营运记录，不能删除；可将状态改为停运 |
| 删除已产生营运记录的驾驶员 | 该驾驶员已产生 N 条营运记录，不能删除；可将状态改为离职 |
| 删除被营运记录引用的区域 | 该区域已关联 N 条营运记录，无法删除；可将其状态改为停用 |
| 删除被叫车需求引用的区域 | 该区域存在叫车需求数据，无法删除；可将其状态改为停用 |
| 人车绑定重复 | 该车辆与该驾驶员已存在生效中的绑定关系 |
| 同车同班次绑定超过 2 人 | 该车辆白班已绑定 2 名驾驶员，请先解绑 |
| 删除已下发/执行中的调度方案 | 已下发或执行中的方案不能删除 |
| 重复提交调度反馈 | 调度单已处于「已完成」状态，不能重复提交 |
| 调度反馈状态非法 | 反馈状态只能是 1 执行中 / 2 已完成 / 3 已拒绝 / 4 已取消 |
| 调度策略非法 | 调度策略只能是 greedy 或 hungarian |
| 预测时长超出范围 | 预测时长需在 1~168 小时之间 |
| 历史数据不足 | 历史数据仅 X 天，不足 14 天，无法可靠建模 |
| 无历史需求数据 | 暂无历史叫车需求数据，请先导入或生成运营数据 |
| 用户角色非法 | 角色只能是 admin/operator/viewer |
| 用户名已存在 | 用户名已存在 |
| 禁用当前登录账号 | 不能禁用当前登录账号 |
| 删除当前登录账号 | 不能删除当前登录账号 |
| 删除内置管理员 | 内置管理员账号不能删除 |
| 参数值类型不符 | 配置项 VEHICLE_SERVICE_RATE 需要数值 |

**处理建议**：直接把 `detail` 展示给用户；前端已按此实现。

### 4.2 401 Unauthorized —— 未登录或令牌失效

表示「没有可用的身份凭证」。响应体固定为：

```json
{"detail": "登录状态无效或已过期，请重新登录"}
```

响应头包含 `WWW-Authenticate: Bearer`。

| 常见触发场景 |
| --- |
| 请求未携带 `Authorization` 头 |
| 请求头格式不是 `Bearer <token>` |
| 令牌签名校验失败（例如使用了不同的 `SECRET_KEY`） |
| 令牌已过期（默认 24 小时） |
| 令牌载荷中缺少 `sub` 字段 |
| 令牌中的用户名在 `sys_user` 表中已不存在 |

**处理建议**：清除本地令牌并跳转登录页。前端 axios 响应拦截器已实现该逻辑，并会把当前路径写入 `redirect` 查询参数，登录后自动返回。

### 4.3 403 Forbidden —— 身份有效但权限不足

表示「知道你是谁，但不允许你做这件事」。有两种情况：

| 场景 | 状态码 | detail 文本 |
| --- | --- | --- |
| 账号被禁用（`sys_user.status = 0`），登录时即被拦截 | 403 | 账号已被禁用，请联系管理员 |
| 账号被禁用后，已签发的令牌再次发起请求 | 403 | 账号已被禁用，请联系管理员 |
| 非管理员调用 admin 接口（10 个系统管理接口） | 403 | 无权限执行该操作（需要管理员） |

**处理建议**：提示用户当前账号无权执行该操作；若是账号被禁用，应引导其联系管理员。

> **需注意的边界**：后端只区分「登录」与「admin」两级权限。只读角色 `viewer` 的业务写操作**在后端与业务页面均未做限制**——一个持有有效令牌的 viewer 直接调用写接口会成功，业务模块页面上的新增/修改/删除按钮对 viewer 同样可见可点；只有管理员专属页面（用户管理、数据维护）通过前端 `isAdmin` 与后端 `require_admin` 双重限制。这是已知的设计不足，详见《系统设计说明》7.3 节。

### 4.4 404 Not Found —— 资源不存在

表示「路径正确、权限足够，但指定 ID 对应的记录不存在」。

| 常见触发场景 | detail 文本 |
| --- | --- |
| 查询/修改/删除不存在的区域 | 区域不存在 |
| 查询/修改/删除不存在的车辆 | 车辆不存在 |
| 查询/修改/删除不存在的驾驶员 | 驾驶员不存在 |
| 解绑不存在的绑定记录 | 绑定记录不存在 |
| 查询/修改/删除不存在的营运订单 | 营运订单不存在 |
| 删除不存在的叫车请求 | 叫车请求不存在 |
| 查询不存在的调度方案 | 调度方案不存在 |
| 提交不存在的调度单的反馈 | 调度单不存在 |
| 查询不存在方案的效果评估 | 调度方案不存在 |
| 查询不存在的预测批次明细 | 预测批次不存在 |
| 修改/重置/删除不存在的用户 | 用户不存在 |
| 修改不存在的配置项 | 配置项不存在 |
| 请求了未注册的路径 | FastAPI 默认 `{"detail": "Not Found"}` |

### 4.5 500 Internal Server Error —— 服务器内部错误

表示「请求本身没有问题，但服务端处理时抛出了未预期异常」。

| 常见触发场景 | detail 文本 |
| --- | --- |
| 需求预测过程中抛出未分类异常 | 预测失败：&lt;异常信息&gt; |
| 仿真数据生成失败 | 数据生成失败：&lt;异常信息&gt; |
| 数据库连接中断、表不存在等基础设施异常 | 服务器内部错误：&lt;异常信息&gt; |
| 其他任何未被捕获的异常 | 服务器内部错误：&lt;异常信息&gt; |

前两种由各自的路由在 `except` 分支中显式转换，第三种由 `main.py` 中注册的全局异常处理器统一转换，目的是**不把调用堆栈直接暴露给前端**，但仍返回异常摘要以便定位问题。

**处理建议**：查看后端控制台日志；若为数据生成或预测失败，通常是数据库连接或数据量问题。

### 4.6 补充：422 Unprocessable Entity —— 参数校验失败

该状态码由 FastAPI + Pydantic 自动产生，不在业务代码中显式抛出，但前端会经常遇到，因此一并说明。

| 常见触发场景 | 举例 |
| --- | --- |
| 路径参数类型不符 | `GET /api/vehicle/abc` → `vehicle_id` 应为整数 |
| 查询参数越界 | `?page=0` → `page` 应 ≥ 1；`?page_size=1000` → 应 ≤ 500 |
| 查询参数枚举不符 | `?group_by=year` → 只能是 `hour`/`day`/`week`/`month` |
| 必填查询参数缺失 | `PATCH /api/vehicle/1/status` 未传 `status` |
| 请求体必填字段缺失或类型错误 | 登录时 `username` 少于 2 个字符 |
| 请求体日期格式错误 | `start_time` 传 `"2026/10/01 8:15"` 而非 ISO 8601 |

响应体为 `detail` 数组，每项含 `type`、`loc`、`msg`、`input`、`ctx`。前端拦截器会把 `loc` 去掉首段（`body`/`query`/`path`）后与 `msg` 拼接为「字段: 消息」的形式提示用户。
